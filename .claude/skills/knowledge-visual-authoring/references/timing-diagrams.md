# SVG 时序图强制布局规范

本规范适用于发送方/接收方、数据帧、ACK、RTT、发送时延、传播时延、处理时延等网络时序图。目标是稳定产出教材式图形：结构清楚、文字清晰、间距均匀、所有标注位于自己的语义区域。

## 1. 失败原因

禁止边画边临时猜坐标。以下做法会产生重叠和飞线：

- 同一个 x 区域同时放时间轴、bracket、竖排文字和说明公式
- bracket 有时向外、有时向内，或两端长度不一致
- 先画线再把文字塞进剩余空白，没有为文字预留槽位
- 用灰色虚线重复描摹已有斜边，造成一条边表达两个含义
- 在倾斜的数据带上放大号文字，却没有计算文字包围盒
- 空间不足时缩小字体，而不是增加 viewBox 高度
- 只检查 SVG 源码，不看实际页面截图

## 2. 固定画布与坐标槽

默认使用横向画布：

```text
viewBox="0 0 1200 720"

页面安全边距：40
标题区：y = 40..90
发送方时间轴：x = 260
接收方时间轴：x = 940
事件几何区：x = 260..940
图内文字安全区：x = 320..880
左 bracket 槽：x = 196..260
右 bracket 槽：x = 940..1004
时间轴顶部：y = 110
时间轴底部：y = 650
```

硬性规则：

- 两条时间轴必须完全平行，使用同一 `y1` 和 `y2`
- 发送方标题固定在左时间轴正上方；接收方标题固定在右时间轴正上方
- 数据帧和 ACK 只能位于两条时间轴之间，端点可以落在时间轴上，但绝不进入 bracket 槽
- 图内说明文字只能进入 `x=320..880` 的文字安全区
- bracket 和竖排耗时文字只进入各自外侧槽，不进入两条时间轴之间的事件几何区
- 普通说明文字不得放在时间轴外侧；公式和补充说明放到图外 paragraph
- 内容超过 720 高时增加 viewBox 高度，x 坐标体系保持不变

先写坐标表，再写 SVG：

| 元素 | x/y 范围 | 文字槽 | 颜色 |
|---|---|---|---|
| 发送方时间轴 | x=260 | 标题 x=260 | `#475569` |
| 接收方时间轴 | x=940 | 标题 x=940 | `#475569` |
| 数据帧 | x=260..940 | 默认不放大字 | `#2563eb` |
| ACK | x=260..940 | 默认不放大字 | `#db2777` |
| 左耗时 bracket | x=212..260 | x=228 | 语义色 |
| 右耗时 bracket | x=940..988 | x=972 | 语义色 |

## 3. 绘制顺序

必须按以下顺序绘制，后一步不得挤占前一步预留的区域：

1. 确定事件时间点和所有 y 坐标
2. 根据标签字数计算每段最小高度
3. 确定 viewBox 高度
4. 画两条时间轴和底部时间箭头
5. 画数据帧/ACK 的几何形状
6. 画水平辅助虚线
7. 在外侧槽画 bracket
8. 最后放文字
9. 执行碰撞检查和浏览器截图验收

同一类事件的垂直间隔必须一致。推荐时间点使用 24px 或 32px 的倍数，不要出现 51、83、117 这类随意间隔。

## 4. 时间段 bracket

bracket 由同一时间轴上的两条短横线和一组竖排文字组成。

### 固定方向

- 发送方左侧 bracket 永远向左：`x1=T, x2=T-48`
- 接收方右侧 bracket 永远向右：`x1=T, x2=T+48`
- 同一 bracket 的上、下短横线长度必须完全相同
- bracket 不得画向主绘图区，不得跨过时间轴
- 只有水平线可作为 bracket 端点；禁止倾斜、禁止悬空

左侧模板：

```svg
<line x1="260" y1="{y1}" x2="212" y2="{y1}" stroke="{color}" stroke-width="2"/>
<line x1="260" y1="{y2}" x2="212" y2="{y2}" stroke="{color}" stroke-width="2"/>
<text x="228" y="{textStartY}" text-anchor="middle" font-size="18" font-weight="600" fill="{color}">
  <tspan x="228" dy="0">发</tspan>
  <tspan x="228" dy="22">送</tspan>
  <tspan x="228" dy="22">时</tspan>
  <tspan x="228" dy="22">延</tspan>
</text>
```

右侧模板：

```svg
<line x1="940" y1="{y1}" x2="988" y2="{y1}" stroke="{color}" stroke-width="2"/>
<line x1="940" y1="{y2}" x2="988" y2="{y2}" stroke="{color}" stroke-width="2"/>
<text x="972" y="{textStartY}" text-anchor="middle" font-size="18" font-weight="600" fill="{color}">
  <tspan x="972" dy="0">传</tspan>
  <tspan x="972" dy="22">播</tspan>
  <tspan x="972" dy="22">时</tspan>
  <tspan x="972" dy="22">延</tspan>
</text>
```

### 段高计算

```text
竖排文字高度 = 字数 × 22px
最小 bracket 高度 = 竖排文字高度 + 24px
```

四个字至少需要 `4×22+24=112px`。如果事件时间不允许这么高：

1. 优先扩大整张图的纵向比例
2. 其次把文字缩短为准确的两字术语
3. 仍放不下时删除该 bracket，在图外文字解释
4. 禁止把字号降到 16px 以下

文字起点使用：

```text
textStartY = y1 + (y2-y1-文字高度)/2 + 16
```

## 5. 数据帧和 ACK

- 数据帧使用蓝色实线平行四边形或两条平行斜线，边界不得进入 bracket 槽
- ACK 使用粉色虚线或细实线，只选择一种表现，不要再叠一条灰色虚线
- 一条线只能表达一个事件；禁止在蓝色数据帧边上叠加“传播时延”虚线
- 传播参考线使用水平绿色虚线，只从一个事件点连到另一条时间轴
- 处理/接收阶段使用时间轴旁的 bracket，不在数据帧内部写竖排文字
- 默认不在斜线带中央写“数据帧”“ACK”大字；标题已能说明时直接省略

确实需要在线上标注时：

- 标签放在斜线中点附近，但与任一边线至少相距 16px
- 字号 18px，最多 6 个汉字或 10 个英文字符
- 使用白色底色遮罩或 `paint-order="stroke"; stroke="#fff"; stroke-width="6"`
- 标签包围盒放不下就移到图外 paragraph，不得压在线上

## 6. 文字排版

- 发送方/接收方标题：22px、600、`text-anchor="middle"`
- 关键时间标签：18px、600
- 普通说明：16px、400/500
- 所有文字与 viewBox 边缘至少相距 40px
- 所有文字与非关联线段至少相距 8px
- 任意两个文字包围盒之间至少保留 12px
- 同一列标签必须共享相同 x 坐标
- 竖排文字只能用于 bracket 内的短术语；公式、RTT 表达式和长句保持横排
- 不得把 `T发送+RTT` 拆成逐字符竖排；把公式放在 bracket 外侧的独立横排槽或文章正文中
- 不得使用 10px、12px 等小字补救空间不足

## 7. 碰撞与越界检查

浏览器渲染后，对每个 `<text>` 调用 `getBBox()`。必须满足：

```text
bbox.x >= 40
bbox.y >= 24
bbox.x + bbox.width <= viewBoxWidth - 40
bbox.y + bbox.height <= viewBoxHeight - 24
```

对任意两个文字包围盒 A、B，使用 12px 安全间距检查：

```js
const overlap = !(
  A.x + A.width + 12 <= B.x ||
  B.x + B.width + 12 <= A.x ||
  A.y + A.height + 12 <= B.y ||
  B.y + B.height + 12 <= A.y
)
```

出现 `overlap === true` 必须调整坐标或扩大画布。不得以“还能看清”为理由保留重叠。

同时逐条检查：

- bracket 的两个端点都在 viewBox 内
- 左 bracket 的 `x2 < x1`，右 bracket 的 `x2 > x1`
- 同一 bracket 上下两条线的 `|x2-x1|` 相等
- 所有数据线的 x 坐标都处于两条时间轴之间
- 任意文字不与非关联线段相交

## 8. 强制验收流程

每张时序图必须完成全部步骤：

1. 将 SVG 放入独立 HTML，背景使用实际页面背景色
2. 按知识文章实际宽度渲染，不只看原始 viewBox
3. 运行 `getBBox()` 文字碰撞检查
4. 截取完整图形截图
5. 放大到 100% 检查字体是否清晰
6. 检查左、右 bracket 是否方向一致且没有飞出画布
7. 检查数据线、ACK 和辅助线是否各自只有一种视觉表达
8. 发现问题后调整坐标，再次截图

只有“零文字重叠、零越界、零 bracket 方向错误”才算完成。不得只回复“已生成”而不做渲染检查。

## 9. 拒绝交付条件

出现以下任一情况必须返工：

- 两段文字包围盒相交或间距小于 12px
- 文字压住时间轴、斜线、箭头或 bracket
- bracket 一端比另一端长，或者方向画反
- bracket、标题或说明文字超出 viewBox
- 使用小于 16px 的正文文字
- 数据帧边界上叠加无语义的灰色虚线
- 同一区域同时出现公式、竖排文字和斜线标签
- 为塞入内容而压缩纵向间距
- 没有实际浏览器截图和碰撞检查结果
