1. 分层架构图（模块视图）

自顶向下共 4 层：UI 调用方 → 主 composable（编排） → 业务搜索（真题 / 知识） → 公共共享层。 上层只依赖下层，useSearch 只做协调，不写具体检索逻辑。

L1 · UI 调用方（外部）
首页 · HomePage.vue
views/HomePage.vue

聊天式搜索界面：防抖搜索框、回车进 chat 模式、结果气泡渲染、highlightText 高亮命中词。

L2 · 编排层（composable）
useSearch · 主 composable
composables/useSearch.ts (93 行)

对外暴露 query、search()、dispose、highlightText。 内部做两件事：① 防抖 + searchSeq 序列号丢过期结果；② 调 searchExam + searchKnowledge 合并结果。

L3 · 业务搜索层
真题精确搜索
composables/searchExam.ts (50 行)
  • parseExactYearNumber：解析 "2019 01" / "2019年1题" / "19年第3题"
  • searchExam：查 examYearNumberMap，命中返回单条结果 + snippet
  • 其余写法一律空数组（不做真题全文检索）
知识文档检索（核心重活）
composables/searchKnowledge.ts (~340 行)
  • expandWithSynonyms：中文子串 + ASCII 整词边界同义词扩展
  • buildQueryContext：lex + segmentit 权重合并 / IDF / 领域归属 / 精准短语
  • scanInvertedIndex：倒排查表 + 倒排未收录词的全文 includes 兜底
  • collectLevelHits：section/point/subpoint/body 分层评分 + 跨领域降权
  • dedupAndSort：同 section 内标题匹配去重 + 精准短语置顶
  • collapseRareTerm：单稀有词命中 + 其余泛词 → 只保留该词命中的前 2 条
  • searchKnowledge：最终构造 SearchResult[]（highlightQuery、examRoute 等）
L4 · 公共共享层
语料加载
ensureCorpusLoaded

全局 Promise 缓存：/search/search-index.json + /search/synonyms.json + 懒加载 segmentit → LoadedCorpus。

词法分析
lexMatchTerms · CJK_RE

拉丁整词 w=4 / 前缀 w=2~3；CJK 整段 w=5；bigram w=3。知识检索 + 高亮共用。

Snippet 截取
extractSnippet

以首个命中 token 为中心，取 maxLen 窗，前后加 …。真题 stem + 知识 body 共用。

高亮工具
highlightText

按 lexMatchTerms 抽取的词（长项优先）在文本里插 <mark>，支持 "io" 匹配 "I/O"。

2. 一次搜索请求的时序流程（用户输入 "TCP 可靠传输" → 回车）

  1. 用户输入 → 触发 search()
    HomePage.vue 回车或防抖到点，调用 useSearch().search('TCP 可靠传输')。1 字符查询直接返回空。
    useSearch.search(q)
  2. 语料懒加载（只加载一次）
    首次访问时并行 fetch 两个 JSON + 动态 import segmentit。后续请求命中全局 Promise 缓存，LoadedCorpus 常驻内存。
    ensureCorpusLoaded()
  3. searchSeq 序列号丢过期结果
    语料 await 可能耗时，期间新的输入会让 searchSeq 自增；resume 时发现 mySeq !== searchSeq 直接 return null，避免旧结果覆盖新 UI。
    runSearch(q) 内部
  4. 真题精确命中（并行于知识）
    尝试解析 "年份+题号" 写法，命中则查 Map 构造一条结果；否则空数组。不参与知识搜索的任何评分。
    searchExam(q, loaded) → exact: SearchResult[]
  5. 知识检索 pipeline：5 步
    ① buildQueryContext：同义词展开 → lexMatchTerms 词权重 + segmentit 位置加权（前词 1.5×）→ IDF 稀有权重 → chapterSignatures 判定 1-3 章领域归属 → 精准短语候选。
    ② scanInvertedIndex：每个 query 词查 invertedK，命中累加权重/最低 tier/命中词集合；倒排未收录的词跑全文 includes 兜底。
    ③ collectLevelHits：section / point / subpoint / body 顺序分层评分；查询聚焦某章时该章 ×1.6、跨章 ×0.7；body 只在所有标题都未命中时才出。
    ④ dedupAndSort：同 section 内标题匹配只留分最高一条（section 级额外 ×1.25 加权）；排序 = 标题层在前 → 精准短语优先 → score 倒序 → 层级 → docIdx。
    ⑤ collapseRareTerm：判定 collapse 集合（整拉丁词 / 整 CJK 段 / 分词器词，去 bigram 和前缀），若正好 1 个稀有词（df≤3）+ ≥1 个泛词（df≥40），只保留命中该稀有词的条目，避免 "prim算法" 把 Kruskal 等只命中"算法"的结果顶上来。
    searchKnowledge(q, loaded, topK)
  6. 构造 SearchResult[]
    slice topK 条，填 blockId、blockIds、matchField、breadcrumb、examCount、score、examRoute（/exams?knowledgeBlockId=xxx）、以及展开后的 highlightQuery。
  7. 合并返回 → UI 渲染气泡
    HomePage.vue 把 { results, exact } 填进 chatTurn。exact（真题）排在最上面单独区块，results（知识）紧随其后。渲染 snippet 时调 highlightText() 插 <mark>。
关键设计点：整个 pipeline 是纯函数式的（除了共享层的 Promise 缓存），所有中间状态都用局部变量和参数传递——QueryContext / DocAccumulator / RankItem[]。 这让每个子函数都能独立测、独立读，不存在 270 行大函数里改同一堆闭包变量的难读状态。

3. 文件清单 & API 详细说明

client/src/search/shared.ts
内部共享 ~240 行
定位：L4 公共共享层。真题 / 知识 / 高亮 都要用到的底层工具集中在这里，避免复制粘贴。 不导出 useSearch 这种顶层 API，被 searchExam.ts、searchKnowledge.ts、useSearch.ts 三者共同依赖。
API / 类型可见性说明
LoadedCorpusexport运行时语料结构：{ knowledgeDocs, invertedK, chapterSignatures, synonyms, examYearNumberMap, segment? }，三者共用。
ensureCorpusLoaded()export全局 Promise 缓存。首次 fetch JSON + 动态 import segmentit；以后直接走缓存。返回 Promise<LoadedCorpus>。
loadSegmentit()内部segmentit 动态 import，任一环节失败都回退 undefined（降级为 bigram，搜索仍可用）。不抛错。
normalizeIo(s)export把 "I/O" / "i / o" 归一为 "io"。查询和文档两侧都用，保证 "IO方式" 能匹配正文 "I/O"。
CJK_REexportCJK 连续段正则（含扩展 CJK / 假名 / 谚文 / 全角符号）。知识的 bigram 抽取 + snippet 的 cjk bigram 共用。
lexMatchTerms(s)export词法分析核心：{ terms: string[], weights: Map<string,number> }。知识倒排、正文 includes 兜底、highlightText 三处都调用。
extractSnippet(text, q, maxLen=70)export以首个 token 为中心截取片段，前后加 …。真题 stem 传 maxLen=100、知识 body 用默认 70。
highlightText(text, rawQuery)export插 <mark> 高亮。长匹配优先避免冲突；"io" 正则特殊处理，能匹配斜杠 "I/O"。HomePage.vue 直接从 useSearch 重新导出的路径 import。
escapeHtml / escapeRegExp内部highlightText 的内部工具，不导出。
client/src/search/composables/searchExam.ts
导出 50 行
定位：L3 真题业务搜索。只有 1 条能力："年份+题号精确命中"，其他一概不管（不做真题全文检索）。 未来如果要做真题全文检索，新建函数在这里追加即可，不会污染知识搜索的命名空间。
API可见性说明
parseExactYearNumber(s)export解析 3 类写法：2019[年.·\-_/，,。\s]*01[题小问]?、\d{2}年第?\d{1,2}[题小问]?。命中 { year: 2019, number: 1 }，否则 null。
searchExam(q, loaded)export解析 → 查 loaded.examYearNumberMap.get('${year}-${number}') → 构造 1 条 SearchResult{type:'exam', isExact:true} 带 snippet。未命中返回 []。
client/src/search/composables/searchKnowledge.ts
导出 2 个 内部 ~13 个 ~340 行
定位：L3 知识检索核心（占代码量最多）。按 rankKnowledgeDocs 编排的 5 个子步骤垂直切分，每个子函数约 30-50 行、只做一件事。 不接触任何 Vue reactive / DOM / UI，是纯数据 pipeline，可以离线单元测试。
API / 类型可见性说明
expandWithSynonyms(q, synonyms)export查询级同义词展开。原文 token 保留 + 中文字串匹配 / ASCII 整词边界匹配（防 IM 误中 prim）+ 命中组把全部变体追加。
searchKnowledge(q, loaded, topK)export对外入口。内部执行 5 步 pipeline 后 slice topK，构造带 highlightQuery / examRoute 的完整 SearchResult[]。
rankKnowledgeDocs(q, loaded, topK)内部纯 pipeline 编排：ctx → acc → items → sorted → collapsed → mapped。
QueryContext内部词权重 / IDF / 领域章集合 / 精准短语 / hasDomainTerm。一次算好贯穿 5 步复用。
buildQueryContext(q, loaded)内部合并 lex 权重 + segment 位置权重（SEG_POS_WEIGHTS[1.5,1.0,0.8,0.7,0.7,0.7]）+ IDF log((N+1)/(df+1))+1 + chapterSignatures 判定 1-3 章。
scanInvertedIndex(ctx, loaded)内部倒排查表累积 tier/score/words；倒排未收录的词对全部 knowledgeDocs 标题+body 做 includes 扫描（兜底 "重定位" 这类被 bigram 切裂但整串出现在正文里的词）。
collectLevelHits(ctx, acc, loaded)内部section/point/subpoint/body 分层评分；领域一致 ×1.6、跨领域 ×0.7；同级用 seenSet 去重；body 仅在所有标题未命中时才出。
dedupAndSort(items)内部同 section 内标题匹配去重（只留一条，section×1.25，同分 section>point>subpoint）。排序 key：标题层 tier=0/body tier=1 → exact精准短语 → score 倒序 → LEVEL_ORDER → docIdx。
collapseRareTerm(ctx, items, acc, loaded)内部稀有词 df≤3（Prim / Kruskal / LRU）；泛词 df≥40（算法 / 方式 / 控制）。命中 1 稀有 + ≥1 泛 → 只保留含该稀有词的条目。防噪声。
SEG_POS_WEIGHTS / LEVEL_ORDER / RARE_DF_MAX / GENERIC_DF_MIN / SECTION_BOOST常量全部魔法数字提出来集中定义，方便调参。
client/src/search/composables/useSearch.ts
对外 API re-export 高亮 93 行
定位：L2 编排层 + 外部统一入口。自身不实现任何检索算法，只做：① Vue composable 生命周期 + 防抖 + searchSeq 并发保护；② 合并 searchExam + searchKnowledge；③ 从 shared 重导出 highlightText 保持现有 import 路径不变。
API / 类型可见性说明
UseSearchReturnexport{ query: ShallowRef, search(override?), dispose() }。
SearchOutcomeexport{ results: SearchResult[], exact: SearchResult[] }。exact 是真题精确命中（0/1 条），results 是知识命中。
useSearch({debounceMs=180, topK=10})export主 composable。runSearch 内部：EMPTY_OUTCOME 常量防空串；mySeq === searchSeq 丢弃过期；异常 return null。
search(override?)内部返回传参 → 立即执行；不传 → 读取 query.value + 防抖 180ms。1 字符或空查询直接返回 EMPTY_OUTCOME，减少噪声。
EMPTY_OUTCOME内部常量{results:[], exact:[]} 对象，所有"空"分支返回同一个引用，避免 UI 侧 shallowEqual 反复刷新。
highlightTextre-export从 @/search/shared 重新导出，保持 [HomePage.vue L5] 现有 import 路径不变。
client/src/search/types/index.ts
类型定义 150 行
定位：所有搜索相关 TypeScript 类型的唯一来源。构建脚本（build-search-index.cjs）也用同一套类型保证 JSON 产物字段对齐。关键类型如下：
类型说明
SearchCorpussearch-index.json 的完整结构（knowledge[] + knowledgeDocs[] + invertedK + chapterSignatures? + exams[]）。
SearchKnowledgeDoc倒排索引单位 = 子点级文档。docIdx 必须等于它在 SearchCorpus.knowledgeDocs 数组中的下标（scanInvertedIndex 用 docIdx 做 O(1) 查表）。
InvertedIndexRecord<string, Array<[docIdx, tier]>>。tier 0 表示该词出现在标题层（section/point/subpoint/book/chapter），tier 1 出现在 body/breadcrumb；标题命中的排序会优先。
KnowledgeMatchFieldsubpoint / point / section / chapter / book / body / breadcrumb。LEVEL_ORDER 映射为数值，分相同时 section > point > subpoint。
SearchResultUI 层消费的统一结果结构。type='knowledge' | 'exam'；知识独有 blockId/blockIds/examCount/examRoute/matchField/pointId/sectionId/highlightQuery；真题独有 year/number/isExact。

4. 文件之间的 import 关系（DAG，无循环）

  • HomePage.vue → composables/useSearch.ts （import { useSearch, highlightText }）
  • useSearch.ts → composables/searchExam.ts , composables/searchKnowledge.ts , shared.ts
  • searchExam.ts → shared.ts （ensureCorpusLoaded 的类型 LoadedCorpus + extractSnippet）
  • searchKnowledge.ts → shared.ts （lexMatchTerms / CJK_RE / normalizeIo / extractSnippet / LoadedCorpus）
  • 以上四个 .ts 文件 → types/index.ts （SearchCorpus / SearchKnowledgeDoc / SearchExamItem / SearchResult / KnowledgeMatchField / InvertedIndex …）
没有循环依赖。最底层是 types/index.ts，往上是 shared.ts，再往上是 searchExam.ts / searchKnowledge.ts 两个叶子，最顶层是 useSearch.ts 做协调。 任何一层只依赖更底层，不会出现 A→B 同时 B→A 的情况。

5. 扩展指引

场景 1：追加一个知识检索调参（如 section 加权 1.25→1.5）

改 searchKnowledge.ts 顶部的 SECTION_BOOST 常量即可，不会波及其他文件。同理 RARE_DF_MAX、GENERIC_DF_MIN、SEG_POS_WEIGHTS 都已集中。

场景 2：追加真题全文检索（不止精确题号）

在 searchExam.ts 里新增 searchExamFuzzy(q, loaded)，逻辑和 searchKnowledge 一样用倒排/includes 即可。然后在 useSearch.ts 的 runSearch 里，用 [...exact, ...fuzzy] 追加到返回结果。不需要碰 searchKnowledge.ts。

场景 3：换一种分词器（从 segmentit 换成 jieba-wasm）

只改 shared.ts 里的 loadSegmentit 内部实现（函数名建议同步改）。上层通过 loaded.segment?.(expanded) 的可选链调用，没有任何地方硬编码 segmentit 的 API。

场景 4：新增一个调用方（如侧边栏 dropdown 用）

从 @/search/composables/useSearch 直接 import { useSearch } from ...，可以传不同的 debounceMs 和 topK。语料是全局缓存，多处调用只加载一次。如果只是纯数据层调用（非 Vue 组件），可以直接 import searchExam / searchKnowledge / ensureCorpusLoaded 走裸函数。
